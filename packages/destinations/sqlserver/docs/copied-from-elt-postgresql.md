# Code copied from elt-postgresql

The SQL Server destination is the third destination that numbers its commits and keeps table targets. The Rule of Three counts places, not packages: knowledge that a third place needs moves into `@eltjs/elt`, and all three destinations use it (ADR 0012). Code that only the SQL dialect makes alike is not one knowledge, and it stays in each destination. Knowledge that only elt-postgresql and this package hold is copied, at strike 2, and a fix in one copy is made in the other copy too, and the commit names both files.

Paths on the left are in `packages/destinations/postgresql/src`. Paths on the right are in `packages/destinations/sqlserver/src`.

## Knowledge in all three, written apart

- The write of the parts of a key: a part with the row hash of its stored part keeps its commit, a changed part is written, and the parts beyond the new count are removed, in the commit of the output row (elt ADR 0026). Each copy keeps it in the SQL of its store, and SQL Server writes the parts of a settled call in one statement for each step, so no part of it is alike in all three apart from the reader view, which moved into elt as `partsView`.
- The external schema: a reader sees the columns of a stream and `loaded_at`. SQL Server keeps it in the columns that `sql-server-writer.ts` gives `TargetReaderView`, as Postgres does, and in the reserved names of `sql-server-identifiers.ts`, which add `_elt_row` and `_elt_key_hash`.
- A load of a connector that is still open when a new load of the connector opens is closed by the new load, and a closed load cannot commit. SQL Server holds a shared lock on the row of the load with `HOLDLOCK`.
- A clear is a load of one commit, which does not close the open loads of its connector (`commitOnce`).
- The DDL of the objects that the targets of one database share takes the lock of its schema in a transaction of its own: an advisory lock in Postgres, an application lock here (`takeLock`), a write transaction of the file in SQLite.
- A view: the three `View` classes take the same declaration and run `refreshView` of elt, which holds the rules of when a view appears, waits or fails, and `DerivedStatus` of elt, which holds the values of each state (S4a found no other part alike in all three). Each copy keeps what its store decides: the session, the SQL of the publication and of the withdrawal, the error of a missing relation, and how it names the relations that the copies make.
