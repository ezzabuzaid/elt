# Phase 02 — Notes and the Apple publication boundary

Dependency: 01. Owner: Notes view definitions, Apple app publication wiring, Apple publication integration tests. This phase establishes the pattern for later Apple phases.

## Read first

`apps/apple/src/pipeline.ts`, `apps/apple/src/main.ts`, `packages/elt/src/core/pipeline.ts`, `packages/elt/src/core/replication.ts`, `packages/destinations/postgresql/src/postgres-writer.ts`, all five Notes stream modules, Google reader-facing warehouse test setup.

## Work

1. Author source-prefixed Notes views beside `sources/apple-notes`, one documented view per stream. Reuse existing stream/column descriptions for unchanged fields; describe aliases, joins and calculated fields where publication adds meaning. Do not duplicate source meaning in a separate metadata catalog. Explicitly describe destination-added `loaded_at` and `attachmentRef` using their current loader/storage semantics. Avoid SELECT * and invented content normalization.
2. Preserve Notes IDs, account/folder hierarchy, Recently Deleted, locked/unavailable bodies, inline attachments and attachment parent chains. Keep native OCR/transcript fields as source text; no parsed attachment content or parser wiring is part of this phase.
3. Wire source publication at the app-owned completed-pass boundary. Use connection identity to select only the relevant source definitions. Retain all-source collection/watch behavior and independent connections; do not restore the superseded generic connector runner.
4. Check actual raw dependencies before initial publication; retry missing bundles on later passes. Install definitions once per startup after readiness. Queryable empty sources count as ready when tables exist. Use the index’s concrete failure contract: record missing targets or publication causes per source in the running app, preserve failure exit status, retry on that source’s next pass, keep other connections watching, and aggregate unresolved causes on shutdown. Leave extraction history untouched. No console/logging or new publication table. A successful retry clears only that source’s unresolved error.
5. Own SQL client disposal and watcher cancellation. Reuse installed types/functions. Change generic ELT only if a concrete gap cannot be solved at the existing app boundary, and record why.

## Checks and exit

Synthetic Notes source → real pipeline → scratch Postgres → agent_reader. Verify all five views and exact comments/types, one locked note, Recently Deleted, nested attachment joins, unavailable bytes vs NULL body, empty initial store. Verify updates/deletes appear without re-publication, restart reinstalls definitions, both absent first-pass dependencies and failed streams with existing empty tables, publication retry after a later pass, failed replacement preserves view definitions/comments while partial raw commits remain possible, independent source progress, and cancellation releases owned clients/watchers. Verify one non-null file reference reads exact synthetic bytes, NULL remains NULL, and a removed record leaves no stale reference in the reader view; reuse storage retention tests rather than duplicate them.

Run `nx run apple:typecheck`, `nx run apple:test`; touched reusable projects get their own Nx checks. If elt changes, run all dependent project checks required by source rules. Use a controlled live service check, not a fixed sleep: run the current Apple executable, monitor the initial attempts/publication for all its configured connections and the required Notes acceptance queries, then send SIGTERM to the PID you own and await clean exit. Bound stalled setup/loads with a documented deadline and classify them as blocked rather than success. An already running old binary cannot prove new wiring; reuse Postgres, and reuse a watcher only if it runs the reviewed code. Obtain authorization before stopping another session’s watcher. Check `finally` disposes publication clients and cancellation waits for native readers. Run this procedure from the implementation session, not this planning review.

Exit: Notes is queryable and the publication boundary is reusable by adding explicit source definitions, without a framework. Record the agreed first-pass/partial/error behavior for phases 03–06.
