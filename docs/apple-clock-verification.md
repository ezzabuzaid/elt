# Apple Clock verification

Checked 2026-10-11 in the shared checkout, with Node 26.10.0, macOS 27.0 (26A428) and Clock 1.1 (62). No repository copy, staging or commit was used. Native objects were created through Clock for the probe and removed through Clock afterward. The stopped default timer and five original cities remain; the originally empty stopwatch is reset. Clock itself retains the removed timer duration with `validRecent = false`.

## Live acceptance

The real `apple-cli:start` setup/sync imported ten streams. With the probe objects present it loaded 1 alarm, 2 timers, 1 duration, 4 sounds, 6 cities, 1 stopwatch and 1 completed lap; the three auxiliary tables were empty. An unchanged sync wrote/deleted zero rows. Changing the alarm label wrote one alarm only. Cleanup deleted one alarm, timer, sound, city and lap, updated the reset stopwatch and invalidated duration, and a final unchanged sync again wrote/deleted zero. All ten `stream_status` records succeeded and all ten checkpoint bindings and states were valid JSON.

With Clock closed, the actual plugin host classes (`ApplePlugin`, connector discovery and `importPending`) imported all ten streams from the real native stores into temporary settings/output. A second import attempt left the completed pass unchanged. This was an in-process host check; the plugin's separate bundled server/setup integration suite passed, but this check did not reconfigure the installed plugin through MCP. Its existing selection was preserved.

After explicit user approval, the previously blocked permission probe ran as the temporary launchd job `com.contextcompiler.clock-read-probe`. It received SQLite `authorization denied` for `local.sqlite` and a permission error for the city plist; the stopwatch plist passed validation. The same three reads succeeded from the granted host. Launchd ran the short script three times before removal (PIDs 7676, 8723 and 9584), with identical results. All three processes exited and the job was removed. No native records or privacy settings were changed. The script and results are `/tmp/clock-probe/access.sh`, `access.out` and `access.err`.

## Mutation proof

The independent prover used the write-test skill's `mutate.mjs` in this checkout because the user forbids copies. Only the new Clock files were mutated. Every applied edit was restored and the compiled mutations had a built-output sentinel. No test or stub was changed after proof. The corrected specification and merged evidence are in `/tmp/clock-probe/mutations/verified-spec.json` and `verified.jsonl`; the original evidence is retained in `final.jsonl` (rows 1, 3, 4, 6, 7) and `retry.jsonl` (rows 2, 5).

| Claim | Deliberate production break                          | Observed failure                                                                    |
| ----- | ---------------------------------------------------- | ----------------------------------------------------------------------------------- |
| 1     | Failed preference reads become empty arrays          | Expected rejection missing                                                          |
| 2     | Saved timer archive becomes null                     | Persisted `fireTime` type is object instead of string                               |
| 3     | Every selected stream wakes for any one store change | Unexpected stopwatch/city streams in the database-change batch                      |
| 4     | Only running timers load                             | Native store has one stopped timer; imported count is zero                          |
| 5     | Clock connector name changes                         | Built-in list contains `clock-mutated` instead of `clock`                           |
| 6     | Clock manifest is omitted                            | Fixed menu navigation reaches Notification Center; Notes account form never appears |
| 7     | Clock settings key changes                           | Switch map contains `clock-settings` instead of `clock`                             |

Each final baseline passed one named test; each mutation failed that named test. All commands used `nx run <project>:test --skip-sync --skip-nx-cache` and a `--command` override of that target's Node runner to place the name filter before the built test file. The source and manifest retries used unique prefixes without commas. A count of one alone was insufficient: Node can report a passing file placeholder when a filter matches no named tests.

## Verification limits

- `calendarReleases`, `makeupDays` and `reports` were empty in both complete inspected databases. This region's Clock UI exposes no operation to create those records. Shapes/relationships are native-model based and synthetic-tested.
- No retained stopwatch-session history was found. Current stopwatch/laps and saved timer durations are exported; this does not establish a universal absence of other-version history.
- Private MobileTimer manager reads failed with service-connection errors. The implementation uses readable local stores and does not require those APIs.
- Permission outcomes were verified on this Mac: database/city reads failed outside the granted host and stopwatch preferences remained readable. This does not establish Full Disk Access as the only authorization macOS can honor, or the behavior of other macOS versions.
